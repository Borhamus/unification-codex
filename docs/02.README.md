## 🎯 Vision & Scope

### What is this?
A full-stack web platform that tracks competitive matches in **Dawn of War: Definitive Edition** running the **Unification mod**, providing:

- **MMR / ELO ranking system** per player
- **Faction vs faction win rate statistics** (all 30+ Unification factions)
- **Match history and player profiles**
- **Balance dashboard** — structured data for the Unification dev team to make data-driven balancing decisions

### What this is NOT
- A mod or game modification
- An official Relic/Unification product
- A replay viewer (not in v1)
- A tournament bracket system (future scope)

### Primary Users
| User | Need |
|------|------|
| Competitive players | See their MMR, ranking, match history |
| Casual players | Browse stats, compare factions |
| Unification devs | Win rate data per faction/matchup to balance the mod |
| Community organizers | Run tournaments with seeding based on MMR |

## ⚙️ How It Works

### Why this is different from dow-de.com

dow-de.com (the inspiration for this project) pulls data from **Relic's official Community API** — match results flow automatically from Relic's servers, no client needed.

**Unification matches don't go through Relic's servers.** The mod runs locally. So we need a different data collection strategy: reading the `.rec` replay files that DOW:DE generates automatically after every match.

```
[DOW:DE + Unification running on player's PC]
            │
            │  auto-generated after each match
            ▼
     [.rec replay file]
     C:\Users\{user}\AppData\Roaming\
     Relic Entertainment\Dawn of War\Playback\
            │
            │  detected by
            ▼
  [DOW Unification Tracker Client]   ← lightweight Python app, runs in background
  - Watches the Playback folder for new .rec files
  - Parses .rec: players, factions, winner, map, duration, mod version
  - Authenticates via player token
  - POST /api/matches → Supabase
            │
            ▼
      [Supabase]                      ← PostgreSQL + REST API + Auth, all in one
  - Stores match data
  - Calculates and updates MMR (ELO)
  - Exposes data via auto-generated REST API
            │
            ▼
     [Next.js Frontend]               ← web dashboard (forked from dow-leaderboards)
  - Leaderboard (ranking by MMR)
  - Player profiles + match history
  - Faction vs faction win rate heatmap
  - Balance dashboard for Unification devs
```

## 🛠️ Tech Stack

### Forked from dow-leaderboards (already built ✅)

|---|---|

| **Tailwind CSS** | Styling |
| **Supabase** | PostgreSQL DB + REST API + Auth + Realtime |
| **GitHub Actions** | CI/CD pipeline |

### New — built specifically for Unification
| Technology | Purpose | Why |
|---|---|---|
| **Python 3.11+** | Client desktop app | Great binary file parsing, easy .exe distribution |
| **watchdog** | Monitor the Playback folder | Industry standard file watcher for Python |
| **struct** | Parse binary .rec format | Built-in Python, handles binary data perfectly |
| **requests** | HTTP POST to Supabase | Simple, reliable |
| **PyInstaller** | Package client as .exe | Players don't need Python installed |

### Why Supabase instead of a custom backend

Supabase replaces what would otherwise be a separate FastAPI server + hosted PostgreSQL database:

- ✅ PostgreSQL database (fully managed, no server to maintain)
- ✅ Auto-generated REST API for every table
- ✅ Authentication (player accounts)
- ✅ Realtime subscriptions (live leaderboard updates)
- ✅ Free tier is sufficient to start
- ✅ dow-leaderboards already uses it — no extra learning curve

## 🗄️ Database Schema

Adapted from dow-leaderboards, extended for Unification:

```sql
-- Players
CREATE TABLE players (
    id          UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    username    VARCHAR(50) UNIQUE NOT NULL,
    steam_id    VARCHAR(20) UNIQUE,
    mmr         INTEGER DEFAULT 1000,
    wins        INTEGER DEFAULT 0,
    losses      INTEGER DEFAULT 0,
    created_at  TIMESTAMP DEFAULT NOW()
);

-- Matches
CREATE TABLE matches (
    id              UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    player1_id      UUID REFERENCES players(id),
    player2_id      UUID REFERENCES players(id),
    winner_id       UUID REFERENCES players(id),
    faction1        VARCHAR(60) NOT NULL,   -- e.g. "death_guard"
    faction2        VARCHAR(60) NOT NULL,
    map_name        VARCHAR(100),
    duration_secs   INTEGER,
    mod_version     VARCHAR(20),            -- e.g. "7.3.8" — key for balance tracking
    played_at       TIMESTAMP DEFAULT NOW()
);

-- MMR History (for player progression charts)
CREATE TABLE mmr_history (
    id          UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    player_id   UUID REFERENCES players(id),
    mmr         INTEGER NOT NULL,
    match_id    UUID REFERENCES matches(id),
    recorded_at TIMESTAMP DEFAULT NOW()
);
```

## 📚 Required Knowledge

### You already have ✅
- Full-stack web development (Next.js + TypeScript)
- REST APIs
- Git / GitHub
- General programming (4th year systems)

### You'll pick up quickly 🔍
| Topic | Difficulty | Where to learn |
|---|---|---|
| **Supabase** | Easy | supabase.com/docs |
| **Binary file parsing in Python** (`struct`) | Medium | Python official docs on `struct` |
| **ELO algorithm** | Easy | Wikipedia article is sufficient to implement |
| **Python watchdog** | Easy | watchdog PyPI docs |

### The hardest part ⚠️
The **`.rec` binary format is not officially documented.** This is the biggest technical unknown of the project. If parsing proves too complex at first, the fallback is a **manual match reporting system** — players self-report results via a simple form — which keeps the project moving while the parser is figured out.

## 🚀 Getting Started

### Prerequisites
- Node.js 18+
- Python 3.11+
- A free Supabase account
- Dawn of War: Definitive Edition + Unification 7.3.8

### Setup

```bash
# 1. Fork and clone dow-leaderboards
git clone https://github.com/YOUR_USERNAME/dow-leaderboards
cd dow-leaderboards

# 2. Install frontend dependencies
npm install

# 3. Copy env template and fill in Supabase credentials
cp .env.template .env.local

# 4. Push Supabase schema
npx supabase db push

# 5. Run the dev server
npm run dev

# 6. Find your DOW replay folder
# C:\Users\{username}\AppData\Roaming\Relic Entertainment\Dawn of War\Playback

# 7. Play a match — a .rec file will appear in that folder
# Open it with HxD hex editor and start mapping the binary structure
```

## ⚠️ Open Questions & Risks

| Risk | Likelihood | Mitigation |
|---|---|---|
| `.rec` format too hard to parse | Medium | Fallback: manual match reporting form |
| dow-leaderboards has undocumented dependencies | Low | Reach out to EnzeD early — he's active |
| Low adoption — players won't install a client | Medium | Single .exe, minimal setup steps |
| Match result cheating | Medium | Require both players to submit matching data |
| Severe faction imbalance corrupts MMR | Low | The data itself helps fix this; filter by bracket |
