## 🗂️ ¿Monorepo o repositorios separados?

**Decisión: Monorepo.**

Razones:
- El cliente Python y el frontend comparten tipos de datos (nombres de facciones, estructura de partidas)
- Un solo repositorio facilita la colaboración con los devs de Unification
- Más simple de mantener para un equipo pequeño
- GitHub Actions puede correr pipelines distintos por carpeta

```
dow-unification-tracker/          ← un solo repo en GitHub
├── apps/
│   ├── web/                      ← Next.js (fork de dow-leaderboards)
│   └── client/                   ← Python desktop app
├── packages/
│   └── shared/                   ← tipos compartidos, constantes, lista de facciones
├── supabase/                     ← schema, migrations, edge functions
├── docs/                         ← documentación técnica y de diseño
└── scripts/                      ← herramientas de utilidad (scraping, seeding, etc.)
```

## 🌿 Git workflow

### Ramas

```
main              ← producción, siempre deployable
develop           ← integración, base para features
feature/xxx       ← una rama por feature
fix/xxx           ← una rama por bug fix
```

### Flujo de trabajo

```
1. Partir de develop
   git checkout develop && git pull

2. Crear rama de feature
   git checkout -b feature/balance-radar-chart

3. Desarrollar + commits semánticos (ver abajo)

4. Push y Pull Request hacia develop
   git push origin feature/balance-radar-chart

5. Review + merge a develop

6. Cuando develop está estable → merge a main → deploy automático
```

### Commits semánticos

```
feat(balance): add radar chart for unit comparison
fix(parser): handle disconnect case in .rec files
docs(rec-format): document byte offsets for faction IDs
chore(deps): update D3.js to 7.9
refactor(mmr): extract ELO formula to shared util
```

Formato: `tipo(scope): descripción en minúsculas`

Tipos: `feat`, `fix`, `docs`, `chore`, `refactor`, `test`, `style`

## 🗄️ Database Schema

### Módulo Ranking

```sql
-- Jugadores
CREATE TABLE players (
    id          UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    username    VARCHAR(50) UNIQUE NOT NULL,
    steam_id    VARCHAR(20) UNIQUE,
    mmr         INTEGER NOT NULL DEFAULT 1000,
    wins        INTEGER NOT NULL DEFAULT 0,
    losses      INTEGER NOT NULL DEFAULT 0,
    created_at  TIMESTAMPTZ DEFAULT NOW()
);

-- Partidas
CREATE TABLE matches (
    id              UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    player1_id      UUID NOT NULL REFERENCES players(id),
    player2_id      UUID NOT NULL REFERENCES players(id),
    winner_id       UUID NOT NULL REFERENCES players(id),
    faction1        VARCHAR(60) NOT NULL,
    faction2        VARCHAR(60) NOT NULL,
    map_name        VARCHAR(100),
    duration_secs   INTEGER,
    mod_version     VARCHAR(20) NOT NULL,
    played_at       TIMESTAMPTZ DEFAULT NOW()
);

-- Historial de MMR (para gráfico de progresión)
CREATE TABLE mmr_history (
    id          UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    player_id   UUID NOT NULL REFERENCES players(id),
    mmr         INTEGER NOT NULL,
    match_id    UUID REFERENCES matches(id),
    recorded_at TIMESTAMPTZ DEFAULT NOW()
);
```

### Módulo Balance Tool

```sql
-- Stats de unidades (cargados desde .rgd o wiki)
CREATE TABLE units (
    id              UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    faction         VARCHAR(60) NOT NULL,
    name            VARCHAR(100) NOT NULL,
    internal_name   VARCHAR(100) UNIQUE NOT NULL,  -- nombre en los archivos del mod
    tier            SMALLINT NOT NULL CHECK (tier BETWEEN 1 AND 5),
    role            VARCHAR(50),                   -- 'anti_infantry', 'anti_vehicle', 'hero'...
    mod_version     VARCHAR(20) NOT NULL,
    -- Stats base
    hp              NUMERIC,
    dps             NUMERIC,
    speed           NUMERIC,
    req_cost        INTEGER,                       -- costo en Requisition
    pow_cost        INTEGER,                       -- costo en Power
    pop_cost        INTEGER,                       -- costo en población
    build_time      INTEGER,
    -- Metadata
    updated_at      TIMESTAMPTZ DEFAULT NOW()
);

-- Power Budget por facción (calculado, editable por devs)
CREATE TABLE faction_power_budget (
    id              UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    faction         VARCHAR(60) NOT NULL,
    tier            SMALLINT NOT NULL,
    mod_version     VARCHAR(20) NOT NULL,
    -- Puntuación por eje
    combat_power    NUMERIC DEFAULT 0,
    mobility        NUMERIC DEFAULT 0,
    economy         NUMERIC DEFAULT 0,
    utility         NUMERIC DEFAULT 0,
    scaling         NUMERIC DEFAULT 0,
    anti_coverage   NUMERIC DEFAULT 0,
    -- Total (suma de todos los ejes)
    total_budget    NUMERIC GENERATED ALWAYS AS 
                    (combat_power + mobility + economy + utility + scaling + anti_coverage) STORED,
    -- Quién lo modificó y cuándo
    edited_by       VARCHAR(50),
    updated_at      TIMESTAMPTZ DEFAULT NOW(),
    UNIQUE(faction, tier, mod_version)
);
```

## 🚀 Cómo arrancar (paso a paso)

### Día 1 — Setup del repositorio

```bash
# 1. Fork dow-leaderboards en GitHub (desde la UI de GitHub)

# 2. Clonar localmente
git clone https://github.com/TU_USUARIO/dow-leaderboards
cd dow-leaderboards

# 3. Renombrar a la estructura del monorepo
mkdir -p apps/web apps/client packages/shared supabase/migrations supabase/functions docs scripts

# 4. Mover el contenido del fork a apps/web/
mv src apps/web/src
mv public apps/web/public
mv next.config.js apps/web/
mv tailwind.config.ts apps/web/
mv tsconfig.json apps/web/
mv package.json apps/web/
mv .env.template apps/web/

# 5. Crear package.json raíz (workspace)
cat > package.json << 'EOF'
{
  "name": "dow-unification-tracker",
  "private": true,
  "workspaces": ["apps/web", "packages/shared"]
}
EOF

# 6. Instalar dependencias del web
cd apps/web && npm install

# 7. Crear proyecto en Supabase (supabase.com) y copiar credenciales
cp .env.template .env.local
# → Editar .env.local con tus keys de Supabase

# 8. Levantar dev server
npm run dev
```

### Día 2 — Setup del cliente Python

```bash
cd apps/client
python -m venv venv
source venv/bin/activate   # Windows: venv\Scripts\activate
pip install watchdog requests pyinstaller

# Crear config.ini desde template
cp config.ini.template config.ini
# → Editar con tu Supabase URL y key
```
